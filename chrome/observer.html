Concepts

Conversation is context. Project is delivery scope. Task is intended work. Dispatch is a handoff. Run is one execution attempt. Span is one operation. Event is evidence.

Project → Task → Prepared task → Dispatch → Run → Span → Event
             ↑                         ↓
       not a Run yet             result / artifacts

Current task answers: what intended work is the Harness orchestrating, and where is that task in its lifecycle?

Run currently shows a wider execution cycle: pre-run handoff, the strict Run execution, and post-run result. A future label such as Execution or Execution cycle may be more precise.

Project readiness is progress for one selected Harness Project. It is not progress of the current ChatGPT conversation. One conversation may touch multiple Projects, and one Project may continue across multiple conversations, devices and executors.

Prepared task is a validated execution envelope waiting to start. Dispatch transfers it into Harness-owned execution and creates/starts a Run. Dispatch does not continue an existing Run and does not accept a result.

Conversation / Turn
  → Current task
  → Prepared → Dispatch → Run
  → Execution spans
  → Transports / background
  → Attribution / evidence
  → Verification
  → selected Project readiness

Actors are tools, transports, models and runtimes observed by the Harness. Attribution links evidence to a conversation/turn. browser_inferred means the chat identity was conservatively inferred from one active browser turn; it is not authoritative transport identity.

Controls

Settings manages explicit Browser Bridge page sharing. Update appears only when the loaded extension differs from disk. Open source chat navigates from scoped evidence to its owning ChatGPT conversation.
