Execution Delivery Harness Browser Bridge

What this is: a local, user-controlled bridge that lets an authorized MCP client such as ChatGPT read text from browser pages you explicitly share. The same local companion also feeds the Browser Bridge Observer.

Current stage

Read-only page bridge: working baseline. Observer: usable local development feature, still evolving.

  • Chrome page sharing and read/find tools: implemented in the current local development worktree.
  • Chrome Side Panel Observer: implemented and locally verified.
  • Firefox Observer page: implemented; Sidebar adapter is not yet verified.
  • Process/OpenCode/Qwen/llama/Git timeline: implemented.
  • ChatGPT Web activity/quiescence: browser-observed WORKING / SETTLING / QUIESCENT is implemented, but remains observer-inferred rather than transport-authoritative until GW-01 owns real dispatch.
  • Firefox Sidebar adapter, Opera observer adapter and public store publication are not yet verified.

Important: the ChatGPT composer may look ready while work is still settling. Use the Observer boundary state as conservative evidence, not as transport authority: QUIESCENT is currently observer-inferred until GW-01 owns the real dispatch boundary.

Connect this browser profile

  1. Start the local companion from the repository with npm start.
  2. Copy the persistent pairing token on macOS with pbcopy < ~/.config/dzzk-jso-bridge/pairing-token.
  3. Paste it below, accept the disclosure and connect. Each Firefox/Chrome profile is paired once; the same companion token is reused.

Default: 43119. The extension connects to http://127.0.0.1:<port>. If the local companion is started with a custom EDH_COMPANION_PORT (including from project .env), enter the same port here.

What page sharing does

Only normal pages you explicitly share are readable. Access expires after 30 minutes and is revoked by navigation, reload, tab closure, extension restart or manual revocation. The bridge reads text; it does not log in, send messages or submit applications.

What the Observer does

The Observer combines completed MCP history, terminal markers, OpenCode/Qwen events, llama.cpp status and Git state into one timeline. It can reconstruct some child-process lifecycles, but completed MCP history is written after a tool returns, so in-flight Remote Desktop calls can still be temporarily invisible.
